# Стандарт сборки статей блога (новый формат)

Эталон: `/blog/semanticheskoe-yadro/` · также в новом формате: `seo-struktura-sayta`, `tehnicheskiy-seo-audit`.

Перенос с WP **≠** новый формат. Новый формат = контент + обложка + интерактивы + вычитка + актуализация.  
Список «новый формат»: `blogNewFormatSlugs` в `src/data/blog-migration.ts`.  
Очередь переноса: `docs/BLOG-MIGRATION-CHECKLIST.md`.

### Пачка за ход

`продолжайN`: **N — учёт пользователя**. Агент за один ход берёт **строго 2** пункта очереди (статья или `dup`). Не ускорять пачками 3+. Текст не ужимать: ориентир 5–7 H2 и развёрнутые абзацы (не «три коротких блока»).

## Чеклист перед «готово»

### 1. Каркас данных

- [ ] JSON: `src/data/blog-posts/<slug>.json` (`title`, `date`, `category`, `cover`, `excerpt`, `lead[]`, `sections[]`)
- [ ] Поле `date` **только для сортировки** (новые сверху) — на сайте дату не показываем
- [ ] Пост подключён в `src/data/blog.ts` (`blogPosts`)
- [ ] Slug короткий, латиница, стабильный URL `/blog/<slug>/`
- [ ] `sanitizePost` / без сырых `\n` в строках, битых HTML-сущностей

### 2. Текст: вычитка и актуализация

- [ ] **Грамматика и пунктуация** (ё, согласование, тире «—», кавычки «ёлочки», лишние запятые)
- [ ] **Расширение и актуализация**: устаревшие сервисы/цифры/UI (AdWords→Keyword Planner, диапазоны Wordstat и т.п.)
- [ ] Убрать обрывки миграции (хвосты таблиц, пустые пункты списка, абзацы не на своём месте)
- [ ] Единый тон: экспертный, без воды; SEO-сроки — по правилу `seo-case-timelines` (подготовка ≠ ТОП)
- [ ] **Правовой дисклеймер Meta** (Instagram / Facebook / WhatsApp): выделенный блок `legalNotice`, не обычный абзац в `lead`. Хелпер `metaProductsLegalNotice([...])` в `blog.ts` → блок `.b-post__legal` (на old WP — розовый `vc_message`). Информационный тон, без призыва пользоваться платформой.

### 3. Обложка

- [ ] AI-картинка в `public/images/blog/<slug>/cover.webp` (**сток запрещён** — см. `image-assets`)
- [ ] Тематика статьи, не абстрактный «офис»
- [ ] **Без текста на картинке** (EN/RU): заголовок только через `getCoverCaption` оверлеем в вёрстке
- [ ] Safe zone ~15% от краёв — превью карточки режет `object-fit: cover`
- [ ] При смене файла — cache-bust (`?v=N` на `<img>`, если нужно)

### 4. Новый формат вёрстки

- [ ] Статья в `blogNewFormatSlugs` → бейдж «Новый формат»
- [ ] Hero: cover + intro (lead, meta, share)
- [ ] TOC при ≥3 H2; sticky на десктопе
- [ ] Progress чтения, время чтения, просмотры, шаринг
- [ ] Prev/next + «Ещё по теме»
- [ ] CTA агентства в конце (`getArticleCta`) — заявка в `/kontakty/`, не чужой продукт

### 5. Интерактивы

Для обучающих / пошаговых SEO-статей — **обязательно**, если материал позволяет:

| Виджет | Файл | Зачем |
|--------|------|--------|
| Чеклист | `BlogChecklist` + `blog-interact.ts` | шаги практики, localStorage |
| Мини-тест / опрос | `BlogQuiz` + `blog-interact.ts` (`quizzes[]`) | проверка усвоения |

Дополнительно по возможности: таблица-пример (`tables`), callout «частая ошибка» (`notes`), FAQ + JSON-LD (`faq`), CSV-шаблон в `public/files/blog/`.

- [ ] Запись в `blogInteractBySlug[slug]`
- [ ] Точки вставки: `afterTitleIncludes` у квизов и чеклиста
- [ ] Клиент: `blog-article-interact.ts` (progress, TOC spy, checklist, quiz)

### 6. Упоминание своих сервисов (Титло и др.)

**Без ERID — только нейтральный статус.**

| Можно | Нельзя (без маркировки рекламы) |
|-------|----------------------------------|
| Имя в ряду инструментов рядом с Wordstat, Key Collector, Rush Analytics… | Выделенный промо-блок, лого, «наш лучший», «пользуемся потому что глубже» |
| Сухое описание функций без оценки и без CTA | Ссылка на `titlo.ru` / «открыть модули» / «старт бесплатно» |
| | Отдельный aside с призывом перейти |

С выделенным блоком и ссылкой — только с пометкой **«Реклама»**, данными рекламодателя и **ERID** (ОРД).  
Кейс разработки `/keysy/web/titlo/` — про работу агентства; не подменять им рекламу SaaS в теле SEO-статьи.

### 7. Листинг и поиск

- [ ] Категория совпадает с рубрикатором `/blog/`
- [ ] `excerpt` для карточки и meta description
- [ ] При необходимости — синонимы/термины учтены поиском (`blog-smart.ts`), без правок ради одного поста

### 8. Финал

- [ ] Локально: `/blog/<slug>/` — TOC, интерактивы, обложка, мобилка
- [ ] Чеклист миграции: `[x]` + пометка **новый формат** при полном стандарте
- [ ] `blogNewFormatSlugs` обновлён
- [ ] **301:** запись в `src/data/blog-redirects.json` (wpSlug, astroSlug, wpId) + `npm run htaccess:blog`
- [ ] Коммит / деплой — по запросу

## 301 редиректы (old WP → Astro)

Источник правды: `src/data/blog-redirects.json`. Генерация: `npm run htaccess:blog` → `public/.htaccess`.

На старом сайте (`old.prime-ltd.su`) permalink: `/%category%/%postname%/`. Дочерние рубрики (`seo-poleznosti`, `smm` и др.) висят под `blog`, поэтому канон бывает одно- или двухуровневым:

- `/blog/{wp-slug}/` — в permalink взята родительская `blog`;
- `/blog/seo-poleznosti/{wp-slug}/` (и аналоги) — взята дочерняя рубрика (в путь входит родитель).

После деплоя на `prime-ltd.su` Apache (fallback после nginx `try_files`) отдаёт 301:

| Откуда | Куда |
|--------|------|
| `/{category}/…/{wp-slug}/` (0+ сегментов из `wpCategories`) | `/blog/{astroSlug}/` |
| `/{wp-slug}/` | `/blog/{astroSlug}/` |
| `/?p={wpId}` | `/blog/{astroSlug}/` |
| дубли (`dup`) | на канон `/blog/{astroSlug}/` |
| часть служебных страниц (`/contact/` → `/kontakty/` и др.) | см. `pages[]` в JSON |

При каждом переносе или пометке `dup` — сразу дописать JSON и перегенерировать `.htaccess`. Не править `.htaccess` вручную.
